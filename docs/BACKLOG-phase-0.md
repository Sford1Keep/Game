# BACKLOG — Фаза 0 (Фундамент)

> Критерий готовности фазы (см. ROADMAP): можно зайти в игру, увидеть персонажа, подвигать его в пустой инстансированной зоне.
> Каждая задача передаётся исполнителю кода отдельно, в порядке ниже (есть зависимости между задачами). Ветка задачи: `task/T-0XX-краткое-описание`, ответвляется от `phase/0-foundation`. Формат коммитов и версий — TECH-SPEC, раздел 8.

## T-001 — Инициализация монорепо

- **Вход:** пустой репозиторий.
- **Выход:** корневой `package.json` с npm workspaces (`packages/*`), базовый `tsconfig.json` (strict mode, наследуется пакетами), `.gitignore`, ESLint/Prettier конфиг на уровне репозитория, пустые пакеты `shared`, `server-api`, `server-instance`, `client` с собственными `package.json` и `tsconfig.json` (наследуют корневой).
- **Критерий приёмки:** `npm install` в корне отрабатывает без ошибок; в каждом пакете есть минимальный `index.ts`, который собирается (`tsc --noEmit`) без ошибок.
- **Связанные разделы:** TECH-SPEC 1, 3, 7.

## T-002 — `shared`: базовые типы

- **Вход:** T-001 закрыт.
- **Выход:** в `packages/shared` — базовые типы для дальнейших задач: `Vector2`, идентификаторы сущностей (`AccountId`, `CharacterId`, `InstanceId`), enum'ы для статуса аккаунта/персонажа. Экспортируются из единой точки входа пакета.
- **Критерий приёмки:** типы импортируются и используются без ошибок компиляции из `server-api` и `client` (проверочный импорт-стаб в каждом).
- **Связанные разделы:** TECH-SPEC 1, 3, 5.

## T-003 — `server-api`: аккаунт (регистрация/вход)

- **Вход:** T-002 закрыт.
- **Выход:** HTTP-эндпоинты регистрации и входа, таблица `accounts` в PostgreSQL (миграция), хранение пароля с хешированием, выдача токена сессии/JWT.
- **Критерий приёмки:** можно зарегистрировать аккаунт и войти через HTTP-запрос, получить валидный токен; повторная регистрация с тем же логином отклоняется с понятной ошибкой.
- **Связанные разделы:** TECH-SPEC 2, 5.

## T-004 — `server-api`: создание персонажа

- **Вход:** T-003 закрыт.
- **Выход:** эндпоинт создания персонажа на аккаунте (один класс-заглушка достаточно для этой фазы), таблица `characters` в PostgreSQL, связь с `accounts`.
- **Критерий приёмки:** авторизованный аккаунт может создать персонажа и получить его данные повторным запросом.
- **Связанные разделы:** TECH-SPEC 5.

## T-005 — `server-instance`: базовая Colyseus-комната

- **Вход:** T-002 закрыт (параллельно с T-003/T-004, не зависит от них).
- **Выход:** минимальная Colyseus room с жизненным циклом (`onCreate`, `onJoin`, `onLeave`, `onDispose`), state schema с позицией игрока (x, y) для каждого подключённого клиента.
- **Критерий приёмки:** можно поднять комнату локально, подключиться тестовым Colyseus-клиентом (скрипт/тест), увидеть, что игрок появляется в state комнаты при join и пропадает при leave.
- **Связанные разделы:** TECH-SPEC 1, 2, 4.

## T-006 — `server-instance`: обработка движения (intent.move)

- **Вход:** T-005 закрыт.
- **Выход:** обработчик сообщения `intent.move` в комнате — авторитетно обновляет позицию игрока в state (без физики/коллизий на этом этапе, просто применение смещения).
- **Критерий приёмки:** тестовый клиент отправляет `intent.move`, позиция в state комнаты меняется соответственно и рассылается остальным подключённым (если есть).
- **Связанные разделы:** TECH-SPEC 4.

## T-007 — `client`: подключение к инстансу и рендер персонажа

- **Вход:** T-005 закрыт.
- **Выход:** Phaser-клиент подключается к Colyseus room (join), рендерит персонажа(ей) по данным из state комнаты (плейсхолдер-спрайт/примитив — арт не нужен, см. TECH-SPEC 9.2).
- **Критерий приёмки:** при запуске клиента виден персонаж на сцене; при подключении второго клиента оба видят друг друга.
- **Связанные разделы:** TECH-SPEC 1, 3, 6.

## T-008 — `client`: движение с локальным предсказанием

- **Вход:** T-006, T-007 закрыты.
- **Выход:** обработка ввода (клавиши/направление) → локальное предсказание движения на клиенте (game-core слой, не завязан на Phaser) → отправка `intent.move` на сервер → реконсиляция позиции при получении обновлённого state.
- **Критерий приёмки:** персонаж двигается отзывчиво при вводе (без ожидания ответа сервера для визуального фидбека), позиция при этом остаётся синхронизированной с авторитетным состоянием сервера (нет расхождения после нескольких секунд движения).
- **Связанные разделы:** TECH-SPEC 4, 9.2.

## T-009 — `content`: пример конфига и фиксация формата

- **Вход:** T-001 закрыт (не зависит от остальных, можно делать параллельно).
- **Выход:** один пример конфига предмета и один пример конфига моба в `/content`, формат (JSON или TS-объекты) зафиксирован; обновлён `/docs/PROJECT-MAP.md` (раздел `/content`) с описанием структуры директорий и формата.
- **Критерий приёмки:** конфиг читается и импортируется (типизированно, через `shared`) в тестовом стабе без ошибок; `PROJECT-MAP.md` отражает реальную структуру.
- **Связанные разделы:** TECH-SPEC 6, 9.2, 9.3.
