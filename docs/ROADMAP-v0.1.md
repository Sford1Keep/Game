# ROADMAP v0.1 — [Рабочее название]

> Разбивка по фазам для нарезки бэклога задач. Каждая фаза — играбельный прирост, не абстрактный этап. Порядок отражает зависимости систем друг от друга, не жёсткие сроки.

## Фаза 0 — Фундамент

Цель: пустой, но работающий каркас, на котором можно начинать наращивать геймплей.

- Структура монорепо (`shared`, `server-api`, `server-instance`, `client`, `content`).
- Аккаунт: регистрация/вход, создание персонажа (один класс на старте достаточно для этой фазы).
- Instance Server: поднятие/закрытие инстанса по запросу, простейшее состояние (позиция игрока) синхронизируется клиент-сервер.
- Клиент: подключение к инстансу, рендер персонажа, базовое движение с локальным предсказанием.
- Content-as-data: минимальный пример конфига (один моб, один предмет) для проверки пайплайна "конфиг → игра".

**Критерий готовности:** можно зайти в игру, увидеть персонажа, подвигать его в пустой инстансированной зоне.

## Фаза 1 — Боевое ядро

- Активная боёвка: атака, уклонение, 1-2 активных способности.
- Сервер-авторитетная валидация урона/попаданий/кулдаунов.
- Простейшие мобы с базовым AI (агро, атака).
- Статусы на мобах (минимум 1-2 для проверки синергии, напр. "уязвимость").

**Критерий готовности:** можно убить моба активной боёвкой, урон и кулдауны считает сервер, а не клиент.

## Фаза 2 — Билд: таланты и инвентарь (базовый слой)

- Общее древо талантов: структура узлов, применение эффектов к персонажу.
- Инвентарь: слоты, экипировка предметов, применение статов/модификаторов навыков.
- Респек общего древа (дешёвый, как решено в GDD).
- Один класс полностью играбелен от начала до простого билда.

**Критерий готовности:** можно менять таланты/экипировку и видеть реальное изменение в бою.

## Фаза 3 — Открытый мир и кооп

- Открытые зоны: фарм, мобы, спавн.
- Кооп: пати до нескольких игроков в общей инстансе, скейлинг мобов/наград по размеру пати.
- Приглашение в свою инстансу.

**Критерий готовности:** двое игроков могут зайти в одну инстансу и фармить вместе с корректным скейлингом.

## Фаза 4 — Классы, возвышение, NPC/квесты

- Остальные стартовые классы (Дальник, Ближник, Призыватель, Друид).
- Классовые ветки талантов + взаимоисключающие развилки возвышения.
- NPC: квестгиверы, гейткиперы локаций/механик.
- Личные квесты (включая квесты возвышения).
- Групповые квесты (опциональный трек).

**Критерий готовности:** все классы играбельны, есть хотя бы одна развилка возвышения на класс, NPC открывают контент по квестам.

## Фаза 5 — Сюжетная кампания

- Структура квестовой цепочки кампании (обучение → локации/рост → финал).
- Гейты локаций по сюжетному прогрессу.
- Интеграция с внешним источником текстов/лора (квестовые тексты подключаются по структуре, заданной здесь).

**Критерий готовности:** можно пройти игру от старта до открытия эндгейма по сюжетной цепочке.

## Фаза 6 — Лут и экономика

- Полная система редкости, аффиксов (включая фракционные).
- Улучшение предметов с риском поломки, реролл.
- Валюта (сезонная) и донат-валюта (постоянная).
- Трейд между игроками + аукцион.

**Критерий готовности:** предметы можно улучшать с реальным риском, обмениваться и продавать через аукцион.

## Фаза 7 — Эндгейм: рогалик и испытания

- Рогалик-режим (открывается после кампании), процедурная генерация, боссы каждые N этажей.
- Недельные мутаторы.
- Спидран-лидерборд (фикс. сид, таймер, отдельные таблицы соло/пати).
- Еженедельный ивент-челлендж (фикс. условия, очки).
- Фильтр лидербордов по друзьям/гильдии.

**Критерий готовности:** эндгейм полностью играбелен, есть минимум один соревновательный формат с честной серверной валидацией.

## Фаза 8 — Гильдии и территориальные войны

- Структура гильдии (роли, приглашения).
- Карта территорий, рейды захвата, накопление счёта.
- Цикл подведения итогов (3 дня), передача владения.
- Пассивные бонусы владения территорией.
- Гильдейский лидерборд по вкладу + распределение призов.

**Критерий готовности:** гильдии могут бороться за территорию и получать от неё пользу.

## Фаза 9 — Сезонная модель

- Механизм сброса персонажей/сезонной валюты.
- Сохранение постоянных данных (донат-валюта, косметика) между сезонами.
- Первая уникальная сезонная механика (минимальная, для обкатки пайплайна "новый сезон = новый контент").

**Критерий готовности:** можно провести полный цикл смены сезона без потери непостоянных данных.

## Фаза 10 — Косметика, шеринг билдов, полировка

- Косметическая система (аккаунтовая, отдельно от силы).
- Экспорт/импорт/сравнение билдов + веб-превью без аккаунта.
- Общая полировка UX, доработка по итогам внутреннего тестирования.

**Критерий готовности:** версия, готовая для первого внешнего тестирования/раннего доступа.

---

## Разделитель обновлений (нумерация)

Для последующих обновлений после первого релиза используется формат `X.Y`:
- **X** — крупное обновление (новая система, новая фаза контента уровня фаз выше).
- **Y** — минорное обновление внутри той же системы (баланс, новый контент по существующим системам: новые предметы/квесты/территории и т.д.).

Сезонные обновления нумеруются отдельно как `Season N`, независимо от X.Y — сезон может выйти между минорными обновлениями и не обязан совпадать с ними по контенту.
